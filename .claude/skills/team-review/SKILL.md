# team-review

レビュー対象・比較元: $ARGUMENTS
1. 読取りレビューのみ実施する。ファイル変更、commit、push、配備は行わない。
2. CLAUDE.md、案件情報、仕様と受入条件を確認する。比較元が不明なら推測で差分範囲を決めず確認する。
3. 変更箇所と関連コードを読み、仕様漏れ、認証認可、入力検証、データ整合性、並行処理、互換性、例外・復旧、テスト不足を調べる。
4. 検証実行は安全な環境と明示された許可範囲でのみ行う。未実施を成功と書かない。
5. 指摘は重要度、場所、再現条件、影響、根拠、修正案を添える。根拠が弱いものは要確認として区別する。好みだけの指摘を重大問題にしない。
出力: 重大な指摘から列挙 / 要確認 / 受入条件の不足 / 確認済み範囲 / 未検証。
問題が見つからなくても品質保証や業務承認の代替とはしない。
