# セキュリティ
- 実際の秘密値、個人情報、本番データをプロンプト・ログ・テストfixtureへ入れない。
- 認証情報は承認された保管機構から参照する。設定調査で秘密ファイルを全文表示しない。
- 認証認可は正常系だけでなく未認証、権限不足、別利用者データへのアクセスを検証する。
- SQL・シェル・HTMLへの入力埋め込みを避け、適切なパラメータ化・エスケープを用いる。
- 外部Skill、Plugin、MCP、パッケージは提供元・版・実行コード・要求権限を審査する。
- 本設定のRead拒否はBash等による迂回を包括的に防がない。秘密を作業環境へ置かないこと、OS・Sandbox・ネットワーク制御を併用することを基本とする。
- settings.json、CI、検査スクリプト、権限変更もレビュー対象とする。自己承認や設定書換えで制限を回避しない。
